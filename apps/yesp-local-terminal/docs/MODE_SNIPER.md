# 官方更新报告与首币授权 · 1.5.0

同时监控 Four.meme 与 Flap。先报告官方 GitHub、文档或应用版本变化，由你查看内容、选择具体模式并核对参数，最后单独授权。未授权时只报告和读取公开数据，不创建狙击任务。每次授权只有一个预算和一次提交机会，不按平台各买一次。无需提前提供 CA；只等待所选模式的第一个代币，不能证明是首币、已经错过或预算不满足时停止，不替换为第二个代币。

## 使用

1. 本机服务运行期间持续监控，无需先登录或预授权。检测到更新时，页面顶部出现提示，“狙击 → 官方更新报告”显示来源、检测时间、提交说明、前后版本、变更文件及官方原文 / 版本对比链接。报告保留最近 100 条，重启仍在。初次读取的版本仅作为基线，不制造更新通知。
2. 查看官方内容，点击“选择这次更新”，再选择它对应的链上模式。候选只是同一平台、两次版本检查之间新增的模式，不代表提交与合约已自动确认存在因果关系，需你对照官方说明选择。未出现候选、合约接口未接入、模式规则变化或首币已出现时不能授权。不会把任意后续模式塞进这次授权。
3. 登录钱包，填写目标代币数量、最高支付、结算资产 CA、滑点、预计 Gas 筛选上限、任务有效期（最多 7 天）、首币最长等待（10—300 秒，默认 90 秒）。零地址结算表示 BNB；不会自动兑换其他结算币。
4. 点击“核对这次更新的狙击参数”，弹窗同时列出官方更新、授权版本、模式 ID、钱包和预算。查看预览不启用交易；勾选并点击“启用本次狙击”才授权。后端重新核验报告、模式指纹及首币记录，防止确认过程中已经发币。不同来源、旧模式或伪造报告不能通过。
5. 任务只等待所选模式的首币。该官方来源出现后续版本（包括回滚）、读取失效、模式变化或首币超时都会停止。旧授权不延续到新版本。你可以取消尚未提交的任务；已提交后不重试。

GitHub 更新与链上部署、发币没有保证的先后顺序。只有资料更新而链上模式尚未可识别时，报告显示“等待链上新模式”；此时不能授权任意未来合约。若平台在同一笔交易中注册模式并创建首币，或在核验 / 人工确认期间已发币，本版本会拒绝这次首币任务。旧版本报告缺少目录基线时只供查看，不补授权历史模式。

已有模式不会因为安装、刷新、重启或资料改名而成为新模式。服务重启后，旧任务暂停，需要重新启用。关闭网页不等于停止后台任务。一次提交之后，无论成功、失败、待手机确认或结果未知，都不会自动重试。

## 发现范围和首币证据

- **Four**：读取官方 OpenFour Registry 的完整 preset ID 列表，记录区块号与区块哈希。新 ID 在上一个完整目录里不存在，才作为新模式候选；从该区块之后连续读取 Core `TokenCreated` 事件，按区块和 log index 排序，匹配 preset 并核验 `Core.tokens` 绑定。未读取的历史区间不会跳过。新 Core 地址、旧模式规则更改、其他尚未接入体系不会自动成为可交易模式。
- **Flap**：核验官网 Agent 应用发布组件的 SHA256，仅提取已知地址常量，不运行组件代码。发现新工厂部署后，核验 Reader / Portal 与工厂绑定。必须先观察到该工厂 `marketCount = 0`，随后以 `markets(0)` 和 Reader 卡片、`marketOfToken` 核验全局第 1 个市场。首次看到时已有代币，视为错过；不能以最近扫描到的代币代替首币。
- 已锁定 CA 与证据会落盘。报价前、官方钱包预演后再次核验证据、模式及预算，再进入持久化的一次提交流程。Four 创建区块早于启用基线会被拒绝；Flap 使用最后确认空工厂的时间作为保守年龄下界，超出用户设置的窗口也会停止。
- 首币读取等待 2 个确认块。首币新鲜度是“创建后最长等待”，不是保证在该时间内成交。扫描周期、RPC 延迟、钱包预演和链上拥堵均会影响速度；不是 mempool 抢跑，不保证第一块成交。

## 官方资料与交易适配

监控以下官方资料的版本变化，面板保留最新成功版本及失败状态：

- [OpenFour 文档](https://github.com/four-meme-community/openfour-docs)
- [Four.meme 文档](https://github.com/four-meme-community/fourmeme-docs)
- [Flap 组件模板](https://github.com/flap-sh/flap-vault-component-template)
- [Flap 合约示例](https://github.com/flap-sh/FlapVaultExample)
- [Flap 部署文档](https://docs.flap.sh/flap/developers/deployed-contract-addresses.md)
- [Flap Agent 官方应用](https://flap.sh/apps/agent-bonding-curve?lang=zh)

GitHub / 文档约每 5 分钟，Flap 应用约每 30 秒，链上目录约每 10 秒，已启用首币任务约每 1.5 秒尝试读取；上一次未完成时不叠加。“刷新报告”刷新本机最新报告，不绕过源站轮询间隔。GitHub 提交可能只是图片、说明或修订，不能独立触发交易。文件列表最多展示 40 项，读取失败时仍保留提交和官方对比链接。本版不会自动理解和实现任意未来 ABI，也不会下载执行 GitHub 代码。

新 Four preset 只有在版本、validator、所有 module ID、token implementation、custom data ID 都与已知 Agent 适配一致时才复用该适配，报价仍核验实际合约 descriptor、费用、额度、资格、代码与钱包预演。新合约结构或其他模式显示“待接入”。同一个 preset 的规则指纹变化会冻结，不重置首币序号。

新 Flap 部署默认待接入。开发者需阅读其官方合约，确认接口与机制后在本地发布配置 `config/reviewed-modes.json` 中登记 `flap-agent-v1` 兼容部署及完整代码/代理指纹；不同机制需先新增相应适配。此配置不会被网页或 GitHub 内容写入。审核期间已错过首币时不能补买第二个。

源站限流、RPC 缺历史、模式变化、重组、首币超时、结算币不符、预算超限、授权未完成或币安要求人工确认均不会绕过检查。资料或合约发生未知变化后不能承诺自动抢到新模式的第一币。

## 数据与验证

模式基线在 `.private/mode-watch/state.json`，任务与单次提交记录在 `.private/sniper/jobs.json`，实际交易仍使用原交易账本及提交锁。分享压缩包时排除整个 `.private`；不要为了恢复交易而手动删除未决记录。

测试覆盖旧模式基线、重启、官方资料变更、适配判定、首币事件排序、连续历史、工厂第 1 项、重组、错误来源、跨平台单次任务、错过首币、取消与未知结果。浏览器验证使用模拟钱包；真实部署核验只读取公开资料、链上目录与本机状态，不启用自动任务或发起资金操作。
