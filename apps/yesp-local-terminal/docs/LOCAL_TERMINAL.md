# YESP Local Terminal 1.11.0

Windows 本地交易面板。打开 `http://127.0.0.1:8717`；无需加载 Chrome 扩展。双击项目目录的 `Start-YESP.exe` 会启动后台服务并打开页面，重复启动会复用同一端口。此版本未设置开机启动。

## GMGN 风格界面与行情

默认打开三栏“战壕”：新创建、即将开盘（内盘 ≥80% / 迁移中）、已开盘（已毕业）。支持搜索、平台筛选、进度排序与暂停列表；范围仍为 Agent 专属模式。交易页 K 线区展开“GMGN 数据设置”，填写已有 API Key 后保存，只用于官方行情查询。详见 [GMGN 设置及数据口径](GMGN_CHART.md)。

## 登录与交易

点击“连接钱包”获取二维码，在币安 App 扫码后点击“已扫码，验证连接”。沿用本机官方 Binance Agentic Wallet CLI 的登录会话；Four.meme、Flap、转出共用这个钱包。会话失效需要重新扫码。合约交易仍需要币安开发者模式及对应额度，Agent 市场仍核验 Agent ID 资格。

在“交易”粘贴完整 BSC CA，点击“识别代币”。买入填写**代币数量**，读取当前可买限额；卖出可选 25%、50%、75%、100%。先核对报价、实际数量、结算资产、最大支付、最低到账、网络费和官方预演，再确认提交。结算资产可能是 BNB、BNCB 或其他 ERC20，不自动兑换。授权与交易分别确认。操作结果未知时不要重复发起，可以填已有交易哈希核验。

支持 Four 经典 V2 普通内盘、OpenFour Binance Agent ID preset、Flap 普通内盘、Flap Agent 虚拟份额内盘及毕业领取。Agent 专属内盘直接调用所属合约，不依赖 Pancake 池。Flap 按目标数量反算固定投入，实际到账受滑点影响；虚拟份额卖出按持仓万分比向下取整。详细接口、额度与官方出处见 [机制与支持范围](UNIFIED_PANEL.md)。

**未接入的 DEX 池与特殊模板会明确拒绝交易。此版本不是所有 Four/Flap 模式全覆盖。** 已毕业到 DEX 的币不能继续按内盘卖出。

滑点输入范围统一为 **0.01%–99.99%**（两位小数），默认 1%；普通买卖与狙击均支持 99%。100% 会把固定投入 / 卖出的最低到账降为零，现有交易路径不支持；即使低于 100%，极小数量取整后最低到账为零也会拒绝报价。数量买入会按选定滑点计算最高支付，狙击另有独立的最高支付预算；高滑点不保证成交，也不绕过余额、持仓限额或合约资格。

## 同页转出

“买入 / 卖出 / 转出”在同一张交易卡片。选好 CA 后点击“转出”，自动使用当前代币并刷新持仓；每次填写 BSC 收款地址和数量，无需重新开页面。25% / 50% / 75% / 100% 按重新查询的真实代币余额填写。点击“核对转出”先读取链上余额、精度、币安余额与 Gas 模拟，再检查完整收款地址、CA、数量和网络费，勾选后点击“确认转出”。转出无需买卖滑点。

Flap Agent 毕业前持仓是虚拟份额，毕业并领取真实代币前不能转出；Four Agent ID 专属内盘锁定钱包间转账，迁移后才可转出。面板显示对应限制，不把虚拟份额当代币余额。普通真实代币的转出还须通过代币合约及币安的检查；转账税可能使实际到账少于转出量。BNB 需保留网络费。

换 CA、换方向、换钱包会清空收款输入；修改收款地址或数量会废弃旧预览。转出和买卖共用未决交易锁，未知结果不能重复提交；当前页可刷新状态或填写已存在的交易哈希核验。

## 链上新币

“战壕”只收录 Agentic Wallet 新模式：OpenFour Core 的 Binance Agent ID 专属 preset `1778027615735`，以及 Flap Agent Factory 创建的虚拟份额市场。普通 Four V2、普通 Flap 和其他 OpenFour preset 不进入列表。按官方事件及模式编号筛选，不以币名或 CA 后缀猜测。

Flap 数据源为 [官网 ID AGENT CURVE](https://flap.sh/apps/agent-bonding-curve?lang=zh) 同一套链上目录：Factory `0xC55820f24015bE7c4f18949D9e1363A3609B300e` 的 `marketCount`，Reader `0x18Aa6C93f1887a243fdc348C9A77F5136555174a` 的 `marketPage` 和 `marketCards`。读取最新 100 个市场，按真实创建序号倒序；核验 Reader 工厂绑定、分页完整性、Market 与预测 CA。包含内盘、毕业中和已毕业，避免只扫近期日志漏掉仍活跃的旧市场。显示市场总数、目录更新时间与失败状态，创建序号不会冒充时间。缺少创建交易哈希时链接市场合约。

Flap 目录每 15 秒尝试刷新，Four 目录每 30 秒尝试刷新，均与每 2 秒的创建事件扫描独立。Four 除最近 6000 个区块的创建事件，还从官方 `POST /meme-api/v1/public/token/search` 分别读取 Agent preset 的外盘（TRADE/NEW）、最新（PUBLISH/NEW）、接近毕业（PUBLISH/PROGRESS）各 50 个候选。接口可能有缓存延迟，因此其 TRADE 标签不能直接作为毕业证明；仅在 Core 的代币配置、preset、descriptor、vault 绑定和当前 phase 通过链上核验后展示。phase=3 才归入已开盘，phase=2 归入即将开盘，phase=4 排除。临时失败保留上次已核验值并显示待刷新。

实时事件补充创建交易链接，Four 按 CA、Flap 按市场去重。三个栏各自最多显示 100 个匹配项，外盘不会被大量新币挤掉；可按平台、名称和 CA 筛选。目录返回和展示均有上述范围限制，不是全网全部历史代币目录。战壕外盘可见性不表示新增 DEX 交易适配。

默认每 2 秒尝试扫描一次；读取尚未结束时不会并发叠加。使用 `eth_getLogs` 读取**已上链事件**，不是 mempool 监控，也不保证第一块成交。重复读取最近几个区块以处理短重组。节点异常时保留旧列表并显示错误，不能把旧列表当实时数据。

## 新币头像、资料与分红

新币列表会显示头像、项目简介及官网 / X / Telegram 等元数据链接，保留链上名称与 CA。头像不可用时使用代币简称。简介和外链由项目方提供，不作为链上核验的事实，也不参与交易或狙击条件。

展开“信息与分配明细”查看创建者、结算资产、创建总量（Four）、单钱包上限、税费分配、分红资产、持仓门槛、分红累计和数据区块。市场栏显示内盘进度、池中金额 / 目标；Flap 另显示 Reader 的持有人数、买卖次数和统计完整性。

Four 的买卖税使用 bps / 100 转成百分比，持有人分配权重原单位为 100。分红记账资产使用实际 quote（例如 WBNB，不能写成 BNB）。累计计入持有人分红读取 feeHolder，累计已领取读取 feeClaimed；totalTaxCollected 是全部代币税，totalManualRewards 仅为社区追加分红。最低门槛来自 minShare。分配权重不是收益率，实际分配还取决于活跃权重、有效持仓及派发状态。

Flap Agent 读取官方 marketSettings.launch 的买卖税和四项分配（bps / 100）。这是毕业发行配置；虚拟份额阶段不视为已发放持币分红。本版尚未核验 Flap 分红资产、最低门槛及实际派发累计，显示“未核验”，不能当作 0。具体项目可能还有自定义奖励，简介中的宣称不自动转成已核验分红。

详情后台并发读取，通常每 120 秒刷新；新币事件扫描不等待元数据。元数据成功缓存 10 分钟，失败 1 分钟后可重试；链上详情失败保留上次数据并标为待刷新。创建顺序、目录和扫描周期维持原规则。图片按需加载并使用 16 MiB 内存缓存，只允许已登记的公开 CDN / IPFS 图片，校验真实 PNG / JPEG / GIF / WebP 格式，不运行 SVG、HTML 或外部脚本。

官方机制来源：[Four Agent TaxToken](https://github.com/four-meme-community/openfour-docs/blob/main/docs/mechanisms/binance-agent-id-exclusive.md)、[Four TaxToken 源码](https://github.com/four-meme-community/openfour-docs/blob/main/contracts/token/TaxToken.sol)、[Flap Agent 官方应用](https://flap.sh/apps/agent-bonding-curve?lang=zh)。

## Agent 内盘 K 线

识别 CA 后，在交易页显示真实内盘成交生成的蜡烛图与成交量，无需先登录钱包。支持 1 分、5 分、15 分、1 小时；移动指针查看 OHLC，拖动平移，滚轮缩放，点击“最新”恢复视图。“更早成交”向前加载一个区间。

Four 数据来自所属 Core 的 `TradeExecuted`（同时匹配 token 与该币实际所属、已适配的 Agent preset）；Flap 来自该 CA 绑定 Market 的 `VirtualTrade`。区块时间来自核验 block hash 的真实区块头。价格按用户实际支付 / 到账的原结算币金额除以本次成交数量计算，包含交易费用影响；纵轴为 BNB、BNCB 等原结算币 / 代币或份额，不是美元估价。成交量以代币 / 份额单位计。

每 6 秒尝试刷新可见图表。首次回溯最近 6000 个区块，点击更早可继续加载，最多回溯距当前 96000 个区块；实际起止时间在图下标明。没有成交的时段留空，不补造蜡烛。查询区间边界和当前未结束的 K 线标记为未完整。切换 CA 会清空旧图，旧请求不能覆盖新代币；节点失败时保留上次数据并标记未更新。

此图覆盖 Agent 内盘事件；毕业到 DEX 后只保留能读取到的内盘历史，当前未包含 DEX 的成交。少量成交会只显示少量蜡烛，与“读取失败”分别提示。更早的历史受 RPC 节点支持范围限制；节点拒绝该区间时停止加载并保留当前图表，不补造历史。

## 单次自动狙击

默认策略是“新模式的首币”，不需要 CA，也不按平台分别设置次数。两平台的官方更新先在网页报告。你查看报告、选择对应的已核验新模式，填写目标数量、最高支付、结算资产、滑点、Gas 筛选上限、有效期（30 秒至 7 天）及首币最长等待（10 至 300 秒），核对弹窗并勾选后才授权。没有报告或尚无可识别模式时不能启用；来源再次更新或首币已出现会停止旧授权，不买第二币。完整流程、来源、候选关联范围和首币证据见 [更新报告与首币授权](MODE_SNIPER.md)。

以下为可切换的“指定 CA”策略：

填写目标 CA、目标代币数量、结算资产 CA（零地址代表 BNB）、最高支付、滑点、有效期 30—1800 秒、预计网络费筛选上限。点击核对，检查弹窗中的钱包和所有参数，勾选后点击“启用本次狙击”。**如果目标已经可交易，启用后就可能触发。**

默认每 1.5 秒尝试检查，前一次未结束则跳过。每次读取仍受 RPC、币安预演、网络延迟和钱包确认影响。满足支持范围、可交易状态、余额、额度、预算、币种和预演条件后，最多提交一次。最高支付约束交易结算资产，不含 Gas；预计 Gas 是筛选值，不是钱包最终扣费的硬上限。

- 尚未创建或开放的目标继续等待至到期；余额不足、超预算、资格或模式不支持会暂停。
- 需要授权或币安提示人工复核时暂停，先手动处理再重新设置任务；不会自动扩大授权。
- 一次只允许一个活动目标，活动期间本面板的手动交易与转出提交被阻止。
- 提交前落盘记录，并受原交易账本、Nonce 和提交锁保护。成功、失败、手机待确认、超时和未知结果都不会再次自动买入。
- 关闭网页不会停止后台任务。尚未提交时可点“取消任务”；已提交不能撤销。服务重启后任务暂停，不自动恢复。

默认没有任务。安装、打开页面、识别 CA 和扫描新币不会自动买入。不要同时运行旧扩展和其他工具提交同一钱包的交易。

## 性能与运行

本地 HTTP 直连后台，取消 Chrome Native Messaging 的依赖；同一时刻的 RPC 读取合并批次、相同读取在途去重，避免跨区块旧报价缓存。页面展示最近请求耗时。链上确认速度由节点、链拥堵和钱包决定，不以扫描延迟代表成交延迟。

只监听 `127.0.0.1:8717`。验证 Host、Origin、CSRF，静态资源白名单隔离 `.private` 和钱包数据；不提供任意合约、签名、命令或 RPC 广播接口。不要通过公网反向代理暴露此服务。

新电脑从源码安装：Node.js 24.5 或更新版本，在项目目录运行 `npm.cmd ci`，再运行 `npm.cmd run build:local`，双击生成的 `Start-YESP.exe`。启动器继承用户已经启用的 Windows 手动代理，仅设置子进程环境，不修改系统代理或 PowerShell 执行策略。高级用户可设置 `YESP_RPC_URL` 与 `YESP_SCAN_RPC_URL` 后启动，链 ID 必须为 BSC 56；扫描节点必须支持日志读取。

源码目录不包含可分享的钱包登录状态；Windows 完整压缩包包含运行环境与依赖，但排除 `.private`、登录状态及交易账本。保留原安装目录中的 `.private`，不要为清除未决状态而删除账本。停止服务会中断扫描；未提交任务在下次启动时暂停，已提交交易仍须核验。

## 1.8.0：BNB 补足结算币与快捷买卖

支持的 Four.meme、Flap、Gang 内盘可启用“结算币不足时，用 BNB 兑换差额”。先用现有结算币余额抵扣，再通过币安 Agentic Wallet 市价兑换报价补足差额。页面分别填写兑换 BNB 预算和兑换滑点；目标代币买入滑点单独保留。

点击核对后先显示兑换路径、结算币完整 CA、缺口、固定 BNB 投入、参考到账量与预算；用户确认才提交兑换。等待订单和链上实际到账核验后，点击“继续核对本次买入”，重新核对精确授权（如需要）和目标代币买入，每一步单独确认。不会自动循环兑换、重复提交或在页面刷新后买入。已完成的兑换无法因后续买入失败而撤回，多余结算币留在钱包。

币安的市价兑换在执行时重新报价，展示的最低到账是参考值；到账不足、没有可用流动性、资格失败或超过预算会停止。预算限制本次固定兑换投入，不含 Gas；预留 0.005 BNB 供网络费检查，这不是最终收费上限。WBNB 使用已有的单独包装流程，原生 BNB 市场直接买入。

新增 10 万 / 100 万 / 500 万代币快捷买入核对，25% / 50% / 全部持仓快捷卖出核对。比例卖出在一次报价中读取最新余额；不会根据旧页面余额直接下单。报价显示钱包、合约读取和币安预演耗时。

交易读取只在同一次操作、同一个已固定区块内合并重复 RPC；下一次预览和提交前重新读取。平台路由提示有界缓存，合约状态、余额、资格、代码与待处理交易校验仍保留。


## 1.9.0：一次点击执行买卖与结算兑换

本地交易页默认勾选“一键执行”。填写数量、买卖滑点、兑换滑点与 BNB 支付上限后，点击“一键买入”或快捷数量按钮，即授权本次完整流程：余额不足时兑换差额、必要的精确授权、内盘买入。一次点击“一键卖出 → BNB”或快捷卖出比例，会出售当前数量，并仅把本次实际所得换回 BNB。原生 BNB 市场无需兑换；WBNB 卖出所得直接 withdraw。页面中间不再二次确认；币安要求的手机确认仍需在 App 完成。

BNB 上限限制本次新增 BNB 投入，不含 Gas；已有结算币先抵扣，另用于买入。买入过程锁定最初结算币、市场、目标数量及报价范围，只补资一次，最多清零并精确授权两步。失败、未知结果、超出预算、风险提示或 180 秒时限会停止后续步骤，不自动重新下单。已完成的兑换或出售不会回滚。服务重启只核验已提交步骤，不自动恢复未提交步骤；结果不明时保留持久交易锁。

后台立即返回受理结果，通过事件流展示各步骤进度。时间分别记录本机受理、首笔提交和全部到账；“受理”不代表成交。去除面板确认往返和重复钱包检查不会消除链上顺序依赖，整体 2 秒不能保证。行情查询不提交订单，“仅核对报价（不提交）”继续保留。转出仍使用单独确认。

## 1.9.1：兑换到账精度兼容

修复 BNB 兑换结算币已成功、面板却报 FUNDING_SETTLEMENT_MISMATCH 并锁住后续交易的问题。币安兑换的实际原生币支付可能因整数拆分舍入比请求金额少 1 wei。只对完全匹配且状态 FINISHED 的官方订单允许少付 1 wei；多付、少付超过 1 wei、钱包或 nonce 不匹配、错误订单或回执仍拒绝。已记录交易哈希也必须继续验证官方订单。

中断任务恢复时只核验已有兑换，记录实际投入与到账量，结束旧任务并解除未决限制；不会自动补买或重复兑换。后续由用户按当前余额重新发起交易，优先抵扣已有结算币。

兼容币安授权预演返回的科学计数法。大整数展示值必须等于本地精确数量的标准浮点表示，同时逐项验证 approve calldata 中的 spender 和原始整数、零支付、钱包、代币、授权变化和风险信息。链上授权使用原始整数，不从展示值反算、不增加授权数量。错误金额或 calldata 仍拒绝。


## 1.9.2：毕业外盘买卖与转出恢复

已识别且通过合约核验的 Gang / Four.meme / Flap 毕业代币接入币安 DEX 市价单：买入直接用 BNB，卖出直接回 BNB。包括 GANG 结算币自身。按购买数量反算固定 BNB 投入，受预算上限约束；外盘使用主滑点，不重复显示兑换滑点。预演页明确显示 DEX 报价，市价单执行时重新报价，实际到账可能少于目标，部分成交与退款会记录且不自动重试。未知模式、迁移中、额外限制或缺少可用流动性仍停止。

官方订单身份、固定投入、链上钱包、nonce、回执、实际代币变动及区块确认共同核验；卖出允许币安为授权所需的最多两个前置 nonce。转出缺失交易哈希时，从只读钱包历史寻找候选，再严格匹配原钱包、nonce、CA、收款地址、数量与 calldata 后核验；不会重新转账。

回归验证使用模拟交易；真实环境只读查询与报价，没有替用户买入、卖出或转账。链上确认和手机确认时间无法保证在 2 秒内完成。


## 1.9.3：预算不足原因可见

预算不足会显示目标数量、BNB 上限、结算币缺口、上限内的预计兑换量及滑点检查量。平台可买额度明确标注不是预算可买数量。零提交的失败记录显示“报价阶段停止，未提交交易”，不再显示已到账步骤保留或空步骤列表。旧记录也使用明确提示，无须修改原交易记录。预算、数量、滑点及重试限制保持不变；仅修正 DEX 因实际钱包余额受限时误报预算不足的错误分类。


## 1.9.4：按数量兑换与清零授权兼容

普通买入和一键买入改为输入目标代币数量，自动计算所需支付、抵扣已有结算币、只兑换缺口，不再要求手填固定 BNB 上限。新请求显式使用 quantity 模式；旧预算请求与历史记录继续执行原限制。钱包余额、Gas 预留、滑点、首份报价范围、单次兑换和提交去重仍受检查。狙击的预授权预算保持不变。DEX 买入按数量反算固定 BNB 投入，实际到账依滑点及成交回执，不承诺严格等于目标数量。

修复币安将 approve(spender, 0) 返回为 Revoke 且省略展示金额时的 APPROVAL_PREVIEW_MISMATCH。仅允许原始 calldata 的金额为零、授权合约及 spender 完全匹配、预演最终 allowance 为零的清零操作；非零授权仍需精确匹配。旧失败任务不会自动重新提交。


## 1.9.5：Gang 一键买入锁定首次投入

Gang 一键流程在首次报价时锁定结算币投入。兑换与授权后沿用同一投入，最低到账仍按最初目标数量和用户滑点计算，不重新按目标数量追涨，不叠加滑点。仅当实时输出仍满足原最低到账量时继续；超出范围、市场或结算币变化则停止。该参数仅在服务器内部传递，网页请求不能指定任意固定投入。


## 1.9.6：手机确认后的回执补查

手动合约交易返回 PENDING_CONFIRMATION 时保存可用订单号；即便返回中没有订单号，也可从官方历史寻找候选交易，并严格比对原始钱包、nonce、合约、calldata 和支付金额后核验回执。只补查已提交交易，不重复发送、不追加买卖。多步流程的交易链接优先显示最后一步哈希。


## 1.9.7：完整流程验证与交易读取优化

成交后自动更新当前代币持仓，避免买入后卖出按钮仍为零余额状态。兼容币安把大整数授权数量显示为四舍五入普通十进制的情况，仍逐字验证原始 calldata 与精确额度。

参考 [TMTN](https://github.com/bnbxcs/TMTN/blob/main/engine/live/rpc.js) 的节点冷却设计，交易读取在主节点网络异常、限流或响应格式异常时最多切换一次备用 BSC 节点；失败节点冷却 30 秒，单节点超时 3.5 秒。每批核对链 ID，合约 revert 原样处理，不重试下单。页面底部显示当前主／备用节点。

独立的链 ID／区块高度、钱包余额／nonce／授权查询改为并行，同一报价内按固定区块复用读取；不跨报价缓存执行数据。订单每一步显示报价、钱包提交、回执核验耗时。币安手机确认和链上确认时间仍由实际网络决定。

增加独立模拟账本，连续验证 BNB → 结算币 → 清零旧授权 → 本次数量授权 → 买入 → 卖出 → 仅把本次所得换回 BNB，并覆盖 WBNB、价格变化、手机确认、失败不重复发送。模拟测试不连接真实钱包。


## 1.10.0：Gang 新币买 1%，翻倍卖半

顶部新增独立「Gang 狙击」页。只接收本轮确认启动后，已核验的 Gang 主网合约目录中新创建的代币。启动时建立链上目录基线，之后等待两个区块再识别增量，按 ERC20 totalSupply 的 1% 计算目标买量（原始单位向下取整）。不按战壕网页排序或 API 时间认定新币，历史币与重复 CA 不会补买。当前覆盖七个已核验部署，未来新合约需先审核接入。

默认模拟监控，单币投入和本轮总预算留空，必须自行填写。选择真实交易并核对钱包、单币 BNB 估值上限、累计预算、最多次数、有效期、新币等待窗口和两种滑点后才启动。一次确认覆盖本轮参数内的结算币兑换、本次数量授权、买入和止盈；币安要求的手机确认仍按钱包处理。已有结算币先抵扣。每次发起买入按单币上限预占总预算，失败不自动释放，超限或平台额度不足则跳过。

按本次成交单独记录实际买量和成本：半仓可卖出报价折合 BNB 达到整笔买入成本时，仅卖出本次实际买入数量的一半，再将本次所得换回 BNB；奇数原始单位留在余仓。余仓不再自动出售，旧持仓不计入卖出数量。这里的翻倍是半仓可执行报价达到整笔成本，包含报价费用但不含 Gas，并受实际滑点影响；新兑换结算币按已核验的实际 BNB 成交比例计成本，原有结算币按提交时兑换报价估值。

「停止新买入」保留止盈监控；「暂停全部」和有效期结束停止买卖。服务重启后暂停，需核对并恢复原任务，累计额度不重置。已广播交易仍需等待回执。结果不明或持仓减少时暂停并提供「核对已提交交易」，不重复发送。关闭网页不会停止服务中的任务。真实任务运行期间锁定面板手动交易，避免钱包操作冲突。

新增确定性隔离账本、策略状态、链上目录与 HTTP 接口测试，覆盖买入、结算币兑换、授权、卖半换回 BNB、余仓保留、预算、去重、重启、未知结果、重组、持仓变化及 CSRF。测试不提交真实交易。
