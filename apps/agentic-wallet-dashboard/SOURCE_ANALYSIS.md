# 源码解析：0.3.5 快照到 0.4.0 本机钱包

本解析基于用户提供的 `binance-agentic-wallet-source-0.3.5.zip`、保留的 0.3.x 文档与当前 0.4.0 源码。ZIP 是用户提供的原始源码快照，不是本次从 Binance 官方下载的看板产品；不能因为使用官方 CLI，就把整套看板称为 Binance 官方代码。未发现明确项目许可证，故未新增许可证或推定再分发授权。

## 改动范围

原快照已有 Node.js HTTP 服务、静态页面、官方 CLI 连接/查询/报价适配、钱包地址绑定、错误脱敏和模拟测试。保留文档记录了 Windows 代理适配、授权地址核验及真实提交关闭等历史行为。0.4.0 在这些边界之上增加 macOS 本机启动入口、实时 PTAH 资产读取和独立的手动 BSC 兑换通道。

| --- | --- | --- |
| 入口 | 直接访问本机地址；保留旧密码模式 | 启动器生成/读取本机访问入口，随机访问密钥换取页面会话 |
| CLI 安装发现 | 项目内依赖为主要入口 | macOS 优先复用已核验全局安装，项目依赖作后备 |
| 账户 | 官方连接、完整地址核对与绑定 | 延续绑定校验，已有官方连接无须重新 signin |
| 授权链接 | 历史固定路径校验可能阻断实际链接 | 核验官方 HTTPS 精确域名及结构后，使用 CLI 返回原字符串 |
| 真实资产 | 官方 CLI 查询 | 额外读取固定 BSC 合约的 NFT 数量和挖矿状态 |

## 访问与钱包绑定

服务只监听 `127.0.0.1`。启动时生成 32 字节随机密钥，写入 `.private/access.json`（`0600`）；所在目录要求 `0700`，并检查目录类型、符号链接及所属用户等条件。

启动器将 `#access=…` 交给浏览器。fragment 不作为 HTTP 请求路径发给服务；页面读取后立即用 `history.replaceState` 去掉它，启动访问密钥只保留在页面内存。这里的“单次带入”是页面初始化传递方式，**不是把进程访问密钥宣称为只能兑换一次的令牌**。没有已保存页面凭证且持有启动访问能力时，才调用受保护的 bootstrap；服务端幂等返回当前有效会话，不因新入口清除正在等待的二维码或已有绑定。

`public/session-recovery.js` 在当前 origin（包含端口）的 `sessionStorage` 中仅保存 `{token, expiresAt}`。这是应用自己的短寿命页面凭证，不是 Binance 官方登录 token；启动访问密钥、官方凭据、地址、资产、交易记录、授权 URL、配对码和 QR 均不写入这份存储。不使用 `localStorage` 或 Cookie 保存页面凭证。复制标签页可能继承 `sessionStorage`，因此不宣称严格唯一标签页隔离。

旧行为在 `pagehide` 主动锁定，且刷新丢失内存 token，导致刷新退出。当前恢复流程在启动、刷新、`online` 和 BFCache 返回时，先用保存的凭证只读请求 `/api/local/state`，恢复 `WAITING`、`REVIEW` 或 `CONNECTED`。等待授权时的 QR 由仍有效的服务端状态重新提供，不从浏览器持久缓存读取。若需要受保护的 bootstrap，之后也只核对状态；整个恢复流程不自动 `signin`、`bind` 或 `submit`。

刷新、关闭页面和离线不主动 lock；明确断开、退出或 401 才清除保存的凭证，并按操作需要使后端会话失效。闲置 10 分钟和最长 1 小时的服务端期限保持不变，关闭后的会话依赖超时回收。页面断开与官方 signout 是不同操作；复制页面、刷新或恢复连接不会延续已失效的官方授权，也不会重新提交在途交易。

获得本机页面会话不等于已绑定钱包。连接流程先检查官方状态；已有连接则读取授权期限、网络和地址，无须再次登录。用户核对完整地址后才建立服务端绑定。后续操作校验当前会话、官方连接、授权有效期及地址，客户端不能任意指定另一个钱包地址读取资产或交易。

未连接时使用 CLI 实际返回的 `urlForWeb`。0.4.0 接受的精确官方域为 `web3.binance.com`、`www.binance.com`、`app.binance.com`，要求 HTTPS，拒绝 userinfo、自定义端口、fragment 和控制字符；校验成功后返回原字符串，不要求旧 `/en/agent-login` 路径，不猜测或重构登录链接。域名接受范围不是对页面内容或账户资格的担保。

应用没有自己的密码收集或云端钱包数据库。CLI 自行管理官方登录；看板不打开凭据文件。此设计依赖本机操作系统账户安全，不是适合公网部署的身份认证系统。

## 官方 CLI 边界

`resolveCliInstallation` 核验安装包名 `@binance/agentic-wallet`、版本 `1.11.0` 以及 `baw` 的公开执行入口 `dist/index.js`。macOS 先查常见 Homebrew 全局安装，再查项目依赖；已有候选安装的元数据不匹配时拒绝执行，不静默执行任意路径。元数据核验是安装位置和已审查版本检查，不等于对整机或包文件做密码学完整性证明。

所有 CLI 子进程均由固定参数数组构造，`shell: false`，使用 JSON 输出。普通适配器仍不允许 `swap`、`send`、任意合约调用、授权变更或挂单写入。独立 `manual-cli.mjs` 只公开受限兑换执行及必要查询；手动引擎进一步限制为 BSC，固定 `--mev true --gasLevel MEDIUM`，拒绝任意命令或额外参数。

1.11.0 是本项目依赖与行为审查基线，不是自动追踪最新版。全局现有安装可以保留已工作的原生钥匙串组件；新机器须按官方安装指引完成依赖和开通，不能用 `npm ci --ignore-scripts` 的成功推断钥匙串可用。

## 实时资产的数据契约

真实资产请求采用 `POST /api/wallet/read`。`kind: "portfolio"` 且 `chainId: "56"` 时，由服务端绑定的地址读取 BNB、USDT、PTAH、Relic、Loom 以及 Mining 的开始时间、储备、可领数量、个人权重和总权重。合约常量来自 PTAH 公共部署资料，不含任何用户地址、持仓或交易。

RPC 只允许固定读取方法、合约和 selector；两个固定公共节点作为查询来源及后备。读取统一使用链头前两个区块的区块标签，校验 chainId、区块时间和结束时的区块哈希，限制并发、响应大小和超时。这减少混合区块读数，不构成最终性保证。

返回包含 `observedAt`、来源、区块信息、各字段状态及 `errors`。数量保留整数或十进制字符串精度。单项失败返回 `null` 并标注部分失败；区块无效时整批数据不可用，不将错误转成零，也不以 `fixtures.mjs` 补齐真实数据。专项响应始终声明覆盖范围，不把固定合约查询当作全部资产发现；没有可靠价格时 `priceUsd`、`valueUsd` 和总估值保持未知。

官方资产列表与专项 RPC 的观察时间可能不同，页面应按各自来源和时间解释。矿机数量及权重只是状态读取，不会主动合成、开始排放、领取收益或执行质押。

## 手动交易：预览、确认、记录与核对

| API（均为同源 POST） | 作用 |
| --- | --- |
| `/api/trade/preview` | 校验当前钱包和输入，读取报价、余额、Gas、交易锁与目标代币风险，生成短期审阅 |
| `/api/trade/submit` | 接收审阅 ID 和明确确认，再校验后将同一意图提交一次 |
| `/api/trade/status` | 按本机意图 ID 读取对应官方订单，核对订单归属和参数，更新本地状态 |
| `/api/trade/list` | 列出当前绑定钱包的本机交易意图记录，不等于完整链上交易历史 |

预览默认有效 120 秒，绑定当前页面和钱包，审阅对象保存在服务端内存。输入包括链、支付/接收代币、数量和滑点；确认时不接受前端替换审阅金额或合约。预览检查源币余额、交易锁和 MEDIUM Gas 报价，并保留最低 `0.001 BNB`。这个保留值只是本地门槛，不是最终 Gas 或授权费用估计。

报价没有给出完整执行成本。界面显示按报价和滑点计算的**参考**最低到账，并要求明确确认最终费用及授权方案尚未完整得知。未知/不支持的代币审计必须明确标记，不能假装检查通过；强风险命中直接禁止提交，不能通过确认框绕过。已列入受信任目标范围的币可跳过目标审计，这不表示支付币一定可卖，也不保证路由、流动性或收益。

提交前再次核验绑定、余额、锁、Gas、报价及风险。报价变差、风险信息变化、审阅过期或缺失必要数据时要求重新预览。预检通过后先持久写入 `SUBMITTING`，再调用官方执行器。重复点击同一意图、并发提交或同钱包尚有未解决订单时，不再次启动财务写入。

```text
短期预览 → 明确确认 → 持久写入 SUBMITTING → 官方提交一次
                                      ├─ 明确未启动/确定拒绝 → FAILED
                                      ├─ 获得订单 ID → SUBMITTED → PENDING → FINISHED / FAILED
                                      └─ 超时/响应不明 → UNKNOWN → 只读核对
```

只有官方明确给出需 App 确认的信息时才可用 `PENDING_CONFIRMATION`，不能从交易锁为 LOCKED 推断确认原因。订单查询必须匹配 ID、链、币对、数量及钱包范围。官方完成状态还须有有效交易哈希；实收读取 `toTokenActualQty`，未返回则保持未知，不能拿 `toTokenQty` 报价填充。

UNKNOWN 表示本地不能确定提交结果，绝不等同失败。超时、解析异常和通用 `SERVICE_ERROR` 均不能证明后台未受理；此时禁止自动重试。已知订单 ID 可继续只读查询；未获得 ID 则需在官方钱包核对历史后人工恢复。页面恢复有效连接后，可重新读取本机交易记录和在途订单状态，不重放确认或提交请求；交易记录本身不放入 `sessionStorage`。关闭页面、断开会话或重启服务不能用来清除未解决意图。

## 持久日志与故障恢复边界

`.private/trades/` 每个交易意图一个受限 JSON 文件，只保留钱包公开地址、币对、数量、订单 ID、哈希、状态和安全错误码等允许字段，不保存页面令牌、官方凭据、原始 CLI stdout/stderr。该信息仍属于个人交易数据，必须排除于 Git 和源码分享。

目录权限为 `0700`、文件为 `0600`；创建采用排他写入，更新使用临时文件、同步和原子重命名。意图的地址、金额、币对和原始审阅字段不可更改；终态不会被旧响应倒退覆盖。提交锁跨进程串行化写入。若进程崩溃留下锁，系统不会自动抢占，须先核对已记录意图；只读状态查询可继续。

这些措施防止本应用在可识别的并发和重启情况下重复提交，不是 Binance 后台或链上“绝对只执行一次”的承诺。删除日志、锁或绕过本机服务会破坏该保护。

## 网络、测试与已知限制

静态页面从本机服务加载，未配置外部遥测或钱包数据云同步。官方 CLI 会访问 Binance 服务，余额 RPC 会向公共节点发送公开钱包地址；公开代币审计只发送查询所需链、合约和请求标识。访问密钥、私钥、密码、登录凭据和 `.private` 内容不上传仓库。

`npm test` 使用替身覆盖参数白名单、官方响应净化、RPC 错链/陈旧/部分失败、会话和 HTTP 来源检查、报价变动、强风险、重复提交、未知结果及日志持久化等行为；测试通过不代表任何真实兑换已执行，也不能替代实时官方资格、流动性、费用或安全检查。本版未执行真币兑换验收；读取 Gas 和交易锁也依赖当时有效的官方登录。

首版手动提交仅支持 BSC。NFT 交易、材料合成、转账、授权变更、自动买卖及后台定时策略没有接入。专用资产读取不是全链资产索引，没有提供 NFT 可实现估值。macOS 是当前主要适配路径，保留的 Windows 代理/启动脚本不能视为本次跨平台实机验收。公共节点、官方报价或审计不可用时可能暂停功能；不采用假数据继续执行。

历史 `README.txt` 及各核查、验收文本仅用于理解 0.3.x 的实现背景。0.4.0 的运行方法见 [README.md](README.md)，具体执行限制以当前代码及官方 CLI 的实际返回为准。

## 扫码入口修正

登录页直接展示 QR 和原始配对码，二维码 payload 与官方 CLI `qrInfo.qrCodeUrl → urlForWeb` 一致。`public/vendor/` 内固定保存 npm `qrcode-generator@2.0.4` 的原始 ESM 编码器和 MIT 许可，不依赖远端 QR 服务。页面使用独立过期定时器，即使状态查询挂起也会清除二维码；离屏生成完成后再次核对当前会话，避免旧结果重新画回页面。服务端对已过期或无有效期限的 WAITING 状态也不再返回 URL 和配对码。原官方 verify 继续等待结束，不自动复用旧码或重复发起登录。
