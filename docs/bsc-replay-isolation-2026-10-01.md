# BSC 历史补扫隔离，第四阶段

## 问题

首三币维护定时器每轮可重复执行同一窗口的 canonical block 检查；每个窗口虽有 archive replay single-flight，整轮检查却没有。Four/Flap 补扫还共用扫描主 RPC 池，跨多个范围连续读取，状态读取限时不能解决这类对象/日志竞争。

23:03:26（北京时间）旧进程快照：标准 RPC 池 active 12、waiting 0，而状态读取 active 0；pending 27,320 + deferred 5,008 = 32,328。累计扫描完成 16,866、实时入队 13,846。实时尾扫当时 degraded，记录 BLXR 日志超时，游标落后约 35 秒。此为部署前事实，不代表新补丁效果。

## 变更边界

- 只在 focus3 且 `BSC_REPLAY_ISOLATION_ENABLED=true` 时启用维护 RPC 隔离；默认开启，关闭开关可回到旧调度，数据无需回退。
- Four 特征 / Flap 首三币重放共用一个维护任务槽，最多 8 个等待唤醒。同 key 合并、不同 key FIFO；队满或冷却只拒绝本轮唤醒，原激活记录和续扫游标仍在 WAL 中。
- 同一种整轮补扫也只允许一轮在途；每轮最多选 2 个窗口，完整巡检轮转选择。与运行轮合并的新激活会在后续官方轮询重新选取，不新建无限 Promise 队列。
- 每个 archive 任务只推进一个日志范围。Four 保留原有有界快速精确命中路径；日志未完成时不写完成标记。
- 维护对象/日志使用独立 RPC 池，标准与 archive 合计最多 1 个逻辑调用，10 秒重试准入预算、最多 2 个节点尝试。实际物理连接仍由公共 host 协调器约束，不增加现有主机限额；不提前释放尚未结束的 RPC。
- canonical block 每次重新读取，不持久缓存重组证据。失败不抹除窗口、CA、slot、pending 或历史覆盖缺口；成功处理完日志范围后才推进游标。
- 失败按 key 退避，尊重更长的 Retry-After；关闭时取消未开始的唤醒并等待已开始的读写，保留断点。
- `_health.maintenanceReplay` 提供运行/排队/合并/退避计数和维护 RPC 槽位。`completed` 是成功结束的维护任务轮次，**不是 CA 完成数或模拟成交数**。

不改交易规则、账本、Jev 配额、TG 广场发送逻辑；不签名或执行实盘。普通 Flap 热索引重放、实时尾扫和覆盖补扫保留各自已有调度；本补丁不是“所有历史任务已清空”。

## 限制

限流和退避只能减少排队/重试竞争，不能补出免费节点本来无法提供的历史合约状态。总积压必须按 pending + deferred 比较，不能把延期当完成。任务预算不是所有候选 1 秒完成的承诺，扫描加速也不等于已经成交或盈利。
