# Four / Flap 更新监控补漏

本轮针对更新发现与观察漏检，不调整收益目标、仓位、RPC 限额或实盘权限。首次读取旧文档只建基线，文档变化不自动成为新代次、CA 证明或买入许可。每次已核实且已适配的更新仍只评估链上创建顺序最早的三个不同 CA，不补第四名。

## 修复范围

| 缺口 | 本轮处理 | 不代表什么 |
| --- | --- | --- |
| Sitemap 只发现页面，许多正文从未轮询；同 URL 规则变化可能不改变能力摘要 | 原慢轮询增加独立正文观察，每轮合计最多 4 页、串行；保留正文指纹、有限前后摘要和待核实变更 | 不代表页面文字已经证明链上部署或新 CA |
| 同一交易内首个 Hook 产生事件后，异步短路跳过后续 Hook | 所有 Hook 逐个执行观察，仍保留首个事件作为返回值；失败进入既有重试 | 不会自动识别未知 ABI 或解除同地址版本核验要求 |
| 普通 X 与重点 X 同时开启时，Four / Flap 重点配置可能丢失 | 按 handle 去重后统一叠加已启用重点配置 | 不代表 X 上游获得完整时间线或零延迟 |
| 面板仅称 Flap 已接入，且网站健康易被误读为狙击全覆盖 | 显示真实受支持来源，分开呈现 X、网站、正文、GitHub、链上状态与未核实变更 | 最近本地检查点不等于追平链头 |

正文观察只接受已配置官方 HTTPS 域名和允许路径，禁止跨页/跨域重定向，不恢复股票/RWA排除项。403/429 使用同源冷却，最低十五分钟并遵守 Retry-After；失败保留上次证据。稳定重读不刷新内容变更时间。最多保留 128 页、32 条待核实变更；溢出单独计数，不声称完整留存。

## 覆盖与限制

发布前只读快照中，合法正文观察名册为 Flap 59 页、Four 10 页（含已有静态正文种子）。旧能力监控的成功不算新正文观察器已建基线。默认每平台每慢周期最多 2 页，理想首次完成需 30 / 5 个周期，另加网络请求时间；错误、冷却、休眠会延长。正文成功后通常三十分钟再检查，是低频补充，不能替代实时链上事件或重点 X。

GitHub 组织元数据检查与提交正文读取分开记录；候选组织仓库不升为已核实来源。未知合约地址、事件 ABI、通用 Hook 同地址新版本仍可能需要新的验证适配。旧网页、转发、同名代币或不明确的公告不会自动建立新买入名额。
