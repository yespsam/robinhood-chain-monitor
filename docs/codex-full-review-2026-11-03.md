# 总评（一句话健康度）

**监控与纸盘基础较完整，但实盘订单持久化、并发限额和风控闭环存在严重缺口，目前不宜据此认定实盘安全。**

审查基于当前完整工作树，不限于 diff：扫描 `src/`、`scripts/` 共 273 个源码/脚本文件，重点深读下单、纸盘、配置、看板及部署调用链；其余模块以静态检索检查为主，不代表全部 12.9 万行均已逐行审计。仓库及上级目录未找到 `AGENTS.md`。

验证：272 个 JS/MJS 文件语法检查通过；KOL 纯函数测试 5/5 通过；另以注入假执行器、内存账本复现下述边界问题。未修改文件、读取 `.env` 实际内容、重启服务或发送交易请求。

## Critical

1. **`src/live-gmgn-trader.js:143`、`:146`、`:154`；`src/paper-strategy-runtime.js:96`——并发下单绕过限额，并覆盖账本。**  
   每次 `buy()` 独立读取账本，在异步确认之后写回旧快照；runtime 又不等待镜像任务完成。**已复现：最大 1 仓、总额 $10 时，两次并发调用提交了 2 单，两次写入却各只有 1 仓。** 后续敞口检查继续低估风险。建议建立跨调用、跨进程的资金预留与订单锁，先原子持久化预留，再提交。

2. **`src/live-gmgn-trader.js:65`、`:146`、`:199`；`src/paper-strategy-runtime.js:1936`——未知成交及账本异常会变成“没有风险记录”。**  
   提交前没有持久化订单意图；轮询超时、断网、进程退出或成交后写盘失败，都可能留下真实持仓而没有账本记录。账本读取异常又统一返回空仓；停机等待列表不包含实盘镜像任务。建议实现 `reserved/submitting/pending/uncertain/confirmed` 状态机，异常时保留额度并禁止新仓；损坏账本必须拒绝交易，启动时先对账。

## High

1. **`src/live-gmgn-trader.js:84`、`:147`、`:154`——日亏损门控没有实际数据闭环。**  
   仓内只找到新增 `open` 持仓及原样保存 `realized` 的路径，未找到条件单平仓后更新持仓、费用和已实现损益的实现。结果是日亏限制无法反映实际亏损，已平仓记录仍占仓位。建议同步成交及条件单状态，按真实成交量、费用和日期更新账本。

2. **`src/live-gmgn-mirror.js:54`、`:88`；`src/paper-safety-policy.js:44`——纸盘实验信号被无差别升级为实盘。**  
   镜像只检查 session 前缀、买入方向和链，并把来源统一改写为 `LIVE_MIRROR_SOURCE`；未核验原始策略、可卖性或审计缺口。主纸盘的部分事件入口明确允许缺失审计字段，因此“纸盘允许试验”可能成为“实盘允许下单”；来源中的 narrative 拦截也无法识别被改写前的来源。建议建立独立实盘策略白名单和安全证据门控，保留原始信号身份。

3. **`src/paper-strategy-runtime.js:1139`；`src/paper-strategy-engine.js:556`、`:771`——定向报价入口漏传 `evidenceTierGate`。**  
   广域扫描在 runtime 第 1610 行传入该参数，定向入场没有传；engine 默认值为 `false`。因此开启的叙事证据、追涨及对应成本门控在快线失效，而该分支随后也执行实盘镜像。建议统一封装两条路径的入场参数，并测试相同候选在两条路径中的拒绝结果一致。

4. **`src/live-gmgn-trader.js:86`；`src/live-gmgn-mirror.js:33`、`:75`——余额与数据新鲜度校验不完整。**  
   `NaN` 余额参与大小比较时不会触发拒绝，已用纯函数复现；余额缺省也可放行。镜像读取价格、余额没有超时或信号有效期，顺序处理多单期间旧纸盘信号仍可继续提交。建议强制有限、非负余额和有效价格，设置请求超时，并在实际提交前重新检查信号及报价年龄。

5. **`src/live-gmgn-trader.js:207`、`:217`——最后一次轮询确认成功仍会报超时。**  
   状态检查发生在请求之前，最后一次 `order get` 的结果没有再检查。**已复现 `orderPollMax=1`、查询返回 confirmed，函数仍抛超时。** 与成功后才记账的设计叠加，会漏记真实成交。建议每次取得结果后立即判定终态，并将超时保存为待对账状态。

6. **`scripts/studio/copy-bot.js:4`；`scripts/studio/risk-bot.js:5`——执行器在线状态和成交/敞口统计均可能误报。**  
   copy-bot 检查 `src/index.js`，但该入口第 456 行只是打印配置；真正镜像由 `dashboard-server → paper-strategy-runtime` 执行。studio 又统计 `kind==='fill'`，镜像成功实际写 `kind:'buy'`。建议监控真实执行器心跳并统一事件 schema；把 **`com.qohfq.yesp-atm-dashboard` 纳入 trader/mirror/runtime 修改后的重启依赖说明**，不能只重启主监控。

7. **`src/paper-strategy-runtime.js:359`；`scripts/dashboard-server.js:273`——可触发实盘的运行实例仍声明“仅模拟”。**  
   runtime 始终输出 `execution:false/signing:false/broadcast:false`，启动日志也标记“仅模拟盘”，但启用 LIVE 后会自动镜像。前端及公共快照边界无法据这些字段识别真实能力。建议区分“纸盘账本属性”和“运行实例的实盘镜像能力”，显式展示启用状态及拒绝原因。

1. **`src/live-gmgn-trader.js:36`、`:131`——tip_fee 已传入，但合法性未校验。**  
   两条 runtime 入场路径最终都经过同一 `buildSwapArgs()`，**未发现 Solana 分支漏传 `--tip-fee` 或 `--priority-fee`**。但 `"0"`、负数和非数字字符串仍可原样传入；已复现 tip 为 `"0"`。建议验证最小值、有限数及合理上限，并把费用纳入余额预留。当前测试只覆盖默认合法值。

2. **`src/live-gmgn-trader.js:191`；`src/live-gmgn-mirror.js:91`——AUTH_IP_BLOCKED 只被记录，没有熔断或恢复状态。**  
   明确拒绝不会被记为成功，这是正确的；但后续信号仍继续尝试，若查询阶段被阻断，已提交订单也没有恢复对账。建议按错误类别进入持久化阻断状态，区分“提交被拒”和“成交未知”。本次未检查实际网络出口，因此不能认定当前 IP 封禁已解除。

3. **`src/kol-news-sniper.js:92`；`scripts/kol-news-sniper.js:77`——每日及每推文限额只统计未平仓。**  
   平仓后记录移入 `closed`，不再计入限制；同一个币也可在同一推文窗口重新买入。**已复现当天已有 4 笔已平仓，仍允许新开仓。** 建议按不可变开仓历史计数，并保存 tweet/token 消费标识。

4. **`src/kol-news-sniper.js:103`；`scripts/kol-news-sniper.js:73`——“出本”实际只回收 88%。**  
   1.6 倍卖出 55%，回款为本金的 `1.6×0.55=88%`，却立即设置 `principalTaken=true`，转入余仓规则。建议按累计净回款判断本金回收；如要在 1.6 倍出本，未计费用至少需卖 62.5%，或者将动作准确命名为部分止盈。

5. **`src/kol-news-data.js:19`、`:34`；`src/kol-news-sniper.js:81`——Solana 地址被小写，资产身份缺少链维度。**  
   Solana 地址大小写敏感，统一小写会改变地址，导致报价和 favorites 匹配失败；以地址单独作键还会混合不同 EVM 链上的同地址资产。建议统一使用 `chain:canonicalAddress`，只对 EVM 地址规范化大小写。

6. **`src/kol-news-data.js:52`、`:99`、`:107`、`:116`——任意底池美元报价缺乏可信度门控。**  
   Dex 选择结果未绑定请求链和 base token；Chainlink 只读取 answer，不检查时间或轮次；decimals 失败默认 18；任意底池只要返回正数就接受，没有深度或价格偏差检查。已用假响应复现“错误链/币对”和“过期 oracle”均被接受。建议校验身份、精度、时间、底池深度和价格偏差；无法验证时保留未知。

7. **`scripts/kol-news-sniper.js:49`、`:57`、`:69`——KOL 入场窗口与报价时间可能失真。**  
   循环开始时固定 `now`，多个网络报价完成后仍用旧时间判断 25 分钟窗口；退出又将报价时间改写为本地当前时间。建议在每笔提交纸盘记录前刷新时钟，保留源报价时间，并拒绝过期 mark。

8. **`src/kol-news-data.js:71`、`:74`——RPC 回退索引可能重复选择失败节点。**  
   循环内同时改变 `rpcIdx` 并使用 `(rpcIdx+i)%length`；两个端点时，第一个失败后第二次仍可能选中第一个。`Promise.race` 超时也没有取消请求或销毁 provider。建议固定本轮起点，成功后更新游标，并释放请求及 provider 资源。

9. **`scripts/studio/market-bot.js:20`；`scripts/studio/risk-bot.js:8`——“权益/日亏”采用了不完整且非每日的口径。**

10. **`src/live-gmgn-trader.js:254`；`scripts/mobile-live-server.js:21`、`:28`——原始 CLI 错误可进入无认证的网络看板。**  
    错误处理仅截断 stdout/stderr，没有脱敏；镜像把错误写入 decisions，手机看板监听 `0.0.0.0` 并返回这些记录。若上游诊断包含凭据或带密钥 URL，就形成泄漏路径；交易详情本身也对可达客户端公开。建议统一错误白名单和脱敏，给移动访问增加认证或可信访问边界。未据此断言已有真实密钥泄漏。

11. **`src/live-env-loader.js:8`；`scripts/kol-news-sniper.js:13`；`.env.example:559`——配置模板和实际加载方式脱节。**

- 实盘默认关闭，有 kill file、来源限制和单笔/总额检查框架。
- Solana condition_orders 的两项费用已集中构造，避免分支重复实现。
- **独立 KOL news 纸盘依赖链未发现 live trader/mirror 入口**，其专用账本目前没有直接实盘执行路径；需区分它与会被镜像的主纸盘。
- 公开快照采用字段白名单；主看板有本机绑定、Host/同源检查；多个纸盘模块已有原子写入、来源绑定及新鲜度校验。
