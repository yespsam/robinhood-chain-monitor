# 模拟盘事件与报价调度修复 · 2026-10-03

## 范围

用户要求解决新底池 / 钱包异动狙击慢的问题。本轮修复本地发现与决策排队，不修改入场策略、安全阈值、真实交易权限或旧账本，不重启 TG/FOMO/扫链进程。使用 GMGN 跟踪与 Web3 安全验证技能区分真实买单、平台标签和核实盈利钱包；不把调度优先级当买入许可。

## 已实现

- `discoverPaperFlowCandidates` 复用按链/CA 建立的资金流索引，避免每个候选重复遍历全量资金流。来源完整性、转仓/卖出排除、同名不同 CA 和地址身份校验保留。
- `cooperative_ca_dispatch_v1`：每个 CA 独立保存待处理报价；重新读取当前证据在账本队列外完成。广泛扫描在纯计算检查点让出给已就绪报价，不再必须等整轮扫描结束。
- 所有成交仍由一个账本写入者处理。构造下一账本后不插入其他写入；若在扫描中已产生成交，广泛扫描按当前账户和当前时钟推进，不覆盖成交。优先检查已有持仓退出。
- 五秒报价有效期不放宽、不改写。提交前核对报价时间/价格身份；丢失证据、错误 CA、过期或已替换报价不成交。诊断新增证据读取、写入排队、准备、评估阶段耗时。
- `local_event_ca_dispatch_v1`：在现有独立估算模拟盘中启动单实例本地证据检查，目标间隔一秒；新 Flap 前三 CA 创建证明和完整、近期的真实钱包净买单按 CA 定向评估，不依赖全市场扫描。
- 事件与队列有时间限制和容量上限，同一事件去重；每次最多纳入 16 个新事件，事件队列 64 个 CA，事件报价目标最多 8 个 CA。保留账户共享请求限速、候选并发和退出优先级，不另开网络配额。
- 缺数据的事件优先进入既有详情队列；详情或 K 线成功返回立即复核该 CA。`research_update` 只是数据完成通知，不充当新推文、聪明钱事件或刷新行情原始时间。

新增离线测试证明：

1. 广泛扫描中途报价返回，可在报价有效期内插入模拟判断，后续扫描写入不覆盖这笔成交。
2. 新底池事件在广泛扫描完成之后到达，独立完成详情 → 报价 → 一笔模拟买入，不调用下一轮广泛扫描，不需要 K 线。
3. 同一事件重复检查不重复开仓、不重复请求报价；原主盘字节不变。
4. 卖出、转账、断档、过期、跨链与未认证前三名事件不成为有效触发。

以上成交来自隔离临时测试目录的明确离线样本，不写入生产账本，也不代表实盘收益。

## 没有冒充已解决的事项

- 第一至第三 CA 的完整创建顺序证明仍只支持 **BSC Flap**。Four 的 first-token 监控与 Flap 的 quote-asset 前三名证明不是同一种协议；本轮没有伪造 Four / Solana 的前三排名，也未扩大支持列表。
- 公开 API 轮询、索引延迟、共享配额与网络延迟仍存在；本地一秒检查不等于链上事件一秒到达，更不保证一秒成交。
- 钱包事件会立即触发原有评估，但没有把单个 KOL 标签买单自动升级为“核实盈利地址免条件跟单”。没有真实报价或合格证据就不制造成交。
- 全量主盘持仓/余额/历史没有重置；十分钟 AI 复盘、Jev 预算、百笔本地复盘和 TG/广场发送设置未更改。
