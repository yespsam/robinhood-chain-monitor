# GMGN Plus 只读调度

2026-09-25：用户确认购买的是 Plus，沿用原 API Key。此变更不含交易签名、广播、真实资金操作或自动发帖，不更改模拟入场/退出规则。

## 生效方式

三个服务加载新代码后，在同一 `data` 目录使用 `gmgn-readonly-plan.json`：`{"version":1,"plan":"plus"}`。配置不存在时仍为 Free。未知套餐、未知字段、损坏文件或软链接拒绝请求，不猜测更高配额。该文件不存密钥。

Plus 在共享进程锁内分配名额，再释放锁等待网络返回；最多 3 个在途，非持仓请求最多占 2 个，留 1 个给优先级 2 的退出检查。本进程队列也保留同一名额，避免排队任务先占满所有位置。后台等待提权保留，已有请求不会被强行打断。Free 保留单请求和 1200 ms 间隔。

官方 Plus 上限是 20 个权重单位/秒。本实现对支持的只读请求统一按最高权重 5 预算，派发间隔至少 350 ms，约 14.29 权重单位/秒，不使用突发容量。并非 20 次请求/秒，也不是每币 350 ms 新价。其他软件及 CLI 自身重试不受该本地门禁直接调度，收到 429 仍必须执行返回的冷却时间。

共享冷却写入使用独立串行锁，合并最长的截止时间，避免并发失败互相缩短封禁。实际 CLI 请求前再次读取共享冷却。超时强制终止只读子进程，工作结束释放名额；进程死亡后的名额可恢复，活进程的名额不会凭时间推测失效。状态损坏时拒绝新请求。

X 监控的 KOL 地址发现改用统一只读客户端，保留原结果数量（最多 100）、身份解析与筛选，不再走无共享限频的旧直连路径。钱包学习保留自身串行节奏，不为消耗额度扩大采样任务。

## 可观测性和回滚

`/api/strategy-state` 的 `cadence.sharedReadonlyPolicy` 显示本地套餐调度、并发及保守权重，**不是服务端套餐认证结果**；`oneSecondKlineEnabled=false`。页面显示 Plus 调度，报价仍显示真实排队/请求耗时与各链数据年龄，不把本地一秒评估当成每币一秒新数据。

### 候选与持仓报价通道修复（2026-09-25 凌晨，v1 历史记录）

共享 Plus 门禁允许并发，但交易运行时仍用单个 `quoteJob` 串行等待全部持仓和候选，旧对照持仓同样占用这条通道。已用离线回归复现：一个持仓报价未返回时，已通过报价准入的候选根本未派发。这是可复现的调度阻塞，不代表所有未开仓都由它造成；当时另有大量形态、成本和数据完整性未通过的候选。

运行时改为 `bounded_exit_candidate_lanes_v1`：Plus 最多一个持仓请求和一个候选请求同时在途，每个链/CA 单飞；每秒只补空闲通道，不等待另一个通道的慢请求。它们仍经原共享队列、350 ms 间隔、3 个总在途/2 个普通请求预算及 429 冷却，不新增采样器、不修改套餐。Free 保持单请求；热降级后先排空既有请求，不增加新并发。退出报价在候选卡住时仍可再次刷新，停止服务会等待两个通道排空。

新增只读诊断：`cadence.quoteConcurrency`、`quoteInFlight`、`lastCandidateQuote` 和 `lastCandidateEvaluation`。最后一次候选报价保留精确链/CA、请求/返回/观察时间、绑定状态和缓存确认条数；最后一次报价触发复核保留请求报价时间、评估实际使用的报价时间、决定及缺失/拒绝原因。两种报价时间可能不同，不能用最后一次事件倒推全部历史拒绝原因，派发和复核数也不是成交数。

不变项：固定每笔总预算 10 U、真实价格及其时间戳、连续报价和形态确认、模型成本、主盘/对照隔离、旧信号去重、原仓冻结退出规则及 paper-only 权限。测试中的买入使用离线夹具，不计作真实行情模拟盘的新订单。首轮运行时 59/59、相关模块 79/79；最终含界面、入口和运行时的组合 78/78（与前述有重叠，不累计成独立测试数）。备份位于 `data/backups/quote-lanes-20260925-axdciP/`；只优雅重载 dashboard，独立主监控/FOMO 未重启。
