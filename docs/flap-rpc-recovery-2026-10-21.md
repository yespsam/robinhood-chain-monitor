- pool 标准/archive/合并/安全错误边界均保留纯 `capacity` 分类及真实等待提示。Flap 对本地未获准发送的等待不增加上游连续失败计数；混合真实 429/超时不会被降级为纯容量等待。
- HTTP 429 仅解析至多 64 KiB JSON 内白名单数值等待提示，与 header 取更长值，不输出原文或凭据；body 不缩短默认一分钟冷却。Flap 保存显式等待至既有一小时状态上限，超过该上限仍由共享 gate 阻止请求。降低本地 backoff 配置或重启不再截短已持久化的等待。
- 补充修复 inner/depth 的明确请求超时（`RPC_TIMEOUT/TIMEOUT/ETIMEDOUT/UND_ERR_CONNECT_TIMEOUT`）被错误扩大为全 host 冷却的问题：与通用 pool 一致，仅冷却失败方法，仍为原 30 秒。429/503 优先整机冷却；连接重置/拒绝、泛 TypeError 仍沿用 host 冷却。既有运行冷却不删除。此处有直接源码证据，但没有逐请求诊断证明某次 NOWNodes 冷却一定由此触发。
