# GMGN AI Trader 策略蒸馏：可借鉴的筛选结构与验证边界

检查日期：2026-11-02（Asia/Shanghai）

用途：研究参考，不替换本项目交易板块，不授权自动买卖、模拟成交或实盘执行。

## 样本与证据范围

检查了本机运行的 GMGN AI Trader 页面，以及其本地代码中的 `app.py`、`README.md`、`SPEC.md`。参考应用代码库当时为干净提交 `416f6d2700b66e714a7506977ff085566ceb5f27`。未读取 `.env`、API key、签名密钥或钱包材料；未连接钱包、调用交易写接口或查看私有实盘成交。

页面展示了候选筛选、风险/钱包特征、LLM 栏和人工买入入口。**页面标签不能证明模型已接入，也不能证明策略有正收益。** 本次没有取得两套策略对同一批 CA、同一时点的完整前向成交样本，故不比较胜率或盈利能力。

## 参考应用实际做了什么

代码实现的是分层漏斗，而不是“Grok 自主交易”：

1. **先做确定性安全/资格筛选**：检查不可卖、蜜罐、税费、rug、bundler、dev 持仓和持有人集中等字段；资料缺失与不安全情况不应被动能分抵消。
2. **再做钱包与市场排序**：使用聪明钱/KOL 数量、短周期价格动能、买卖占比、换手、安全和 dev 维度给候选排序。
3. **补看 dev 历史**：根据历史发币、存活/失败、已清仓和换皮特征调整质量判断。
4. **把候选与执行分开**：筛选结果进入人工决策；实际执行是独立的买卖路径，持仓逃生也单独处理。

需特别纠正“LLM/Grok 已学习并参与交易策略”这一印象：当前 `LLMJudge.judge` 是以短周期涨跌和买入占比为输入的硬编码启发式，返回 pass/watch/reject 与解释文本；我没有在这个运行应用的代码中找到 Grok/xAI API 调用。代码注释把真实 LLM 接入写作后续工作。可能存在于此应用之外的 Grok 学习或对话，本次无法核验，不能据此说它已反馈进这份正在运行的策略。

此外，项目说明中的交易决策日志是追加记录用途，尚未形成读取已实现盈亏、校准阈值并做留出验证的闭环。因此应把它看作**人工筛选工作台与规则基线**，不是已验证的自学习模型。

## 值得借鉴的部分

- 将安全硬门、候选排序、解释、仓位/执行分层；任何语言模型只能解释和给建议，不能覆盖安全阻断、仓位上限或退出条件。
- dev 的历史表现可作为风险特征，而不只盯当前币的单次买盘。
- 用多种相互独立的证据排序，避免一个钱包标签或一个价格指标决定入场。
- 让每次通过/拒绝都留下版本化理由，方便复盘 false positive、漏选和数据缺失。

这些是**结构层面的借鉴**，不建议照搬其数值阈值：本次没有同批样本的统计校准证据。

## 暴露出的弱点

- 所谓 LLM verdict 实际上重述价格动能和买入占比，不理解事件的真实主体、时间线、传播与 CA 归属；不能称为叙事分析。
- 聪明钱/KOL“人数”与“新鲜净买入”不是一回事。旧标签、卖出、转仓和地址簇重叠可能让计数显得强，但并不代表当前资金承接。
- 动能占优仍可能发生在冲高派发阶段；只有短周期涨幅/买盘比例，不能确认首冲后的整理、二次突破或结构失效位。
- 追加日志本身不是学习。若不核实成交、费用与样本选择偏差，不应由模型叙述或少数成功案例自动改阈值。

## 对我们交易板块的蒸馏方式

继续使用本项目自己的候选、买卖、仓位、风险和退出模块；GMGN AI Trader 只作比较基线，不调用它的下单 API，不复制它的订单或直接把它的通过信号转成买入。

- **内盘**：只把精确链/CA、时间、哈希和方向齐全、来源可核验的新鲜聪明钱净买作为观察证据。一般爆量、地址标签、共同交易所入金不代替资格；该观察本身不触发买入。
- **外盘**：研究首段上涨—回撤—有效整理—收盘二次突破，并同时要求原文催化与精确 CA 的关系可核验、筹码/买盘持续、真实流动性和往返成本可接受。价格结构、叙事和钱包证据任一缺失时只观察或拒绝；不能从币名倒推叙事，也不能把结构猜测写成“庄家操盘事实”。
- **模型职责**：若未来另行接入 Grok，只允许它对清洗后的公开材料与结构化数值生成带来源的假设；本地确定性代码校验链/CA、时间、卖出安全、流动性、成本和风险。模型不得自行放行、选择仓位、修改阈值或下单。

## 建议的对照验证，不是本报告启用的功能

如后续开展比较，应先冻结参考规则版本，并在同一批候选 CA 和同一信息时点同时记录“GMGN 参考规则”与“本项目规则”；保留通过与拒绝、失败和缺数据样本，禁止只挑后来上涨的币。只用当时可见的已收盘 K 线与新鲜报价，分别记录叙事原文/来源、钱包净流、阶段判断、报价年龄、费用假设、拒绝原因及后续可观测结果。

比较应以扣除买卖费用、滑点、税费和 Gas 后的净收益为主，并同时看可成交覆盖、盈亏比、回撤、CA 集中度、剔除最大正贡献 CA 后的结果和安全漏检；过期报价或缺失估值为未知，不填零。至少积累 30 个完整回合、10 个不同 CA、7 天以上再做初步复核，并保留独立留出期。这只是发现明显缺陷的起点，不足以证明稳定盈利。

## 结论

可学习的是“安全先行、dev 与钱包特征辅助排序、人工与执行隔离”的架构；不应学习其“看起来像 Grok”或将动能阈值当作已验证优势。报告不修改交易代码、参数、运行进程或账本；未声称该参考策略盈利，也未启用新的影子成交。
