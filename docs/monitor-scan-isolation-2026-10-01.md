## 本次落地

```text
主监控进程：X / 平台 / TG 原发送与去重
  ├─ 持久化命令信箱 → BSC 扫描子进程：实时采集 / 历史补扫 / 唯一状态写入者
  └─ 接收扫描进程的告警请求，沿用原发送路径，原结果确认返回

独立 FOMO 进程：保持原进程，不重启
Dashboard / 模拟盘：保持原进程，不修改账本

主进程与 BSC 子进程的 createRpcPool → 同一份本地 RPC 租约 / 冷却数据库
```

1. 实时容量按当前区块新鲜窗口独立计算。派生的 block-age 索引可从原记录重建；年龄改变只改变容量归类，不删除或伪造完成旧任务。混合过期日志、未来区块仍不能走实时预留容量。整批入队和游标提交保持原子性。
2. 全部 createRpcPool 生产主通道（实时、历史、分类、Flap/Four 固定来源、BSC 元数据、叙事证据）接入跨进程 SQLite WAL 协调：同 hostname 最多 2 个调用，后台最多 1 个；另一个留给实时。方法别名合并。429 / Retry-After 持久化，单个半开探测，旧请求成功不能抹掉后来失败。
3. `src/bsc-scan-worker.js` 由主进程监督，退出后有界退避重启。扫描状态仍只有一个写入者，旧进程未排空前，新进程不能抢写。主进程断开时子进程排空退出，不产生孤儿持续扫链。
4. 发现 / Flap / Four / 底池生命周期注册通过 `bsc-worker-mailbox.sqlite` 持久化；重复内容合并，处理并持久化成功后才确认。失败保留、退避重试，30 次失败保留为 failed，不静默丢弃。信箱最多 2,000 条，满时明确返回背压。
5. TG 没有另开重复发送器。子进程请求仍由主进程的原 narrative / sendAlerts 路径处理，原 delivered / queued / suppressed 结果回传。IPC 超时不伪造发送成功；保留原持久化 outbox 和去重保障。

## 文件与开关

- `src/bsc-queue-pressure.js`：区块年龄分区计数，保留旧算法作为回退。
- `src/rpc-host-coordinator.js`：跨进程 RPC 租约、冷却、探测；只保存 hostname / 方法 / PID / 时间，不保存 URL、凭据或交易参数。
- `src/bsc-worker-mailbox.js`、`src/bsc-worker-client.js`、`src/bsc-scan-worker.js`：持久化信箱与子进程监督。
- `data/bsc-runtime-heartbeat.json`：扫描进程独立心跳；心跳新鲜不等于所有上游健康。
- 默认开启 `BSC_WORKER_ENABLED`、`BSC_SHARED_RPC_ENABLED`、`BSC_QUEUE_ISOLATION_ENABLED`。worker 模式要求共享 RPC 开启。
- 回退进程形态：设置 `BSC_WORKER_ENABLED=false` 后平滑重启主进程。不要在旧扫描进程还活着时另行手动启动扫描器，不要删除数据库 / 原状态 / WAL。
- 使用 Node 内置 `node:sqlite`，本机验证版本 25.8.0；其他部署应使用支持该 API 的 Node 22.16+（22 LTS）或 24+。SQLite 事务不包住网络请求；锁忙短暂退避，不绕过限额。

## 明确保留的限制

- 本次是 **BSC 重型扫描与主监控隔离**，不是把所有链、所有 monitor、模拟盘/UI 一次拆成微服务。Robinhood 的原轻量扫描仍在主进程，模拟盘仍在 dashboard 进程。
- 队列总存储上限仍为 40,000。独立实时容量不是无限存储，也不等于历史积压消失。输入持续大于验证吞吐时仍会触发总量背压，现有 overloaded / stalled 诊断继续真实显示。下一阶段应优化合法的历史证据处理吞吐，不能靠删记录、伪造覆盖或无限加并发掩盖。
- 共享协调范围是已接入的 HTTP RPC 池；既有 WebSocket 快速证明与 Four 的专用原始快速回放仍有各自的窄范围预算，不宣称全应用所有网络请求已由单一调度器覆盖。
- 免费公共 RPC 的 429、历史状态不可用、来源身份验证失败、FOMO 接口缺凭据等，不会因为拆进程自动消失。
