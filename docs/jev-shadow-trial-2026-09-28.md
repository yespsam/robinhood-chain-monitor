# Jev 快速语义判断：一次性旁路试验

## 范围

用户要求“使用 jev 快速决策，你试试”。已按 TypeSafe 官方接口准备独立 CLI，未接入交易运行时。主盘、估算费用盘、余额、持仓、扫描频率、TG 和定时任务不变。脚本不具备签名、广播或账本写入能力。

本次按照叙事分析与 Web3 安全技能，把事件关系、文案状态、需求路径拆成三个结构化 Choice，报价年龄、原文年龄、税率与数据完整性由代码计算。模型不预测价格、不计算金额、不推断庄家身份。平台标签不当成已核实盈利钱包。

## 使用

推荐运行 `node scripts/configure-typesafe-key.js`，打开其本地临时网址，通过密码输入框保存 `TYPESAFE_API_KEY` 对应密钥。配置存入 `.env.typesafe.local`（Git 已忽略，0600 权限），不改写其他提供商设置。该入口仅在 127.0.0.1 开放 15 分钟且只能成功保存一次，不记录请求正文，不显示密钥，不发送给外部服务。保存后回到对话继续一次性测试；脚本不自动调用模型。也兼容原有 `.env` 配置。不要使用 GMGN Key，不要把密钥发到聊天或提交到 Git。官方入口：https://console.typesafe.ai/

```sh
node scripts/probe-jev-shadow.js --dry-run 3
node scripts/probe-jev-shadow.js --live 3
node --test test/jev-shadow-decision.test.js
```

- 默认 dry-run：仅检查当前本地快照及脱敏请求，零外部模型请求；不是 Jev 推理结果。
- `--live`：最多三个不同 CA、每个一次请求、每次最多 2500 ms，不重试、不跟随重定向，不切换其他模型。
- 固定官方 `https://api.typesafe.ai/v1/systemone`，请求 `jev-latest`，记录实际返回版本、耗时、用量和输入指纹。
- 优先有新鲜原文的候选；不足时允许用明确标记的旧原文检验相关性分类，但不会获得“优先复核”。没有可核实来源记录的候选不调用模型。未来时间、跨 CA 原文、缺少原文记录均不补造。
- 只发白名单代币字段、公开来源摘录与汇总市场数值；不发账户、余额、用户钱包、逐笔成交或其他密钥。来源 URL 去除查询参数，正文仅作不可信数据。原文摘录可能不完整，模型未访问或验证原帖。
- 输出为“优先复核／继续观察／排除候选，待核实”，不是成交许可。0.8 是未校准研究阈值，置信度不等于盈利概率。即使输出“优先复核”，也没有执行路径。
- 缺密钥、超时、限流、无原文、无效输出各有独立状态；不得伪装为模型做出的观察决定。

## 验收与限制

离线测试覆盖脱敏、同 CA 原文绑定、未来/陈旧时间、税率与安全信息未知、低置信度、响应结构、固定主机、无重试、超时和失败信息脱敏。离线 fixture 耗时不代表真实 Jev 延迟。

2026-09-28 本次验证：Jev 专项 12/12 通过；连同独立估算盘、亏损修复和 dashboard 的定向回归共 40/40 通过。实时 dry-run 成功读取并按链＋CA 去重 633 个候选，其中 81 个有匹配的来源记录、10 个来源时间在一小时内；这些仅是快照中的记录，不代表已验证消息真实性或可交易。显式 live 探针返回 `missing_key`，外部模型调用数为 0。交易服务保持 enabled，TG 主进程和 FOMO 进程心跳仍在更新；未重启任何服务。

首次检查时本地没有 TypeSafe API Key，因此尚不能报告真实推理耗时、准确率或盈利效果。密钥配置后先运行小样本；若要影响模拟盘，需另行做带人工标签的中文/英文原文、同名币、否认、旧闻和提示注入测试，再与现有规则比较。不能用三条样本证明收益或生产可靠性。

本地密钥入口补充验证：原 `Referrer-Policy: no-referrer` 在内置浏览器中导致同源表单提交被严格 Origin 校验拒绝。改为 `same-origin` 后，使用不写文件的服务和虚构密钥在同一浏览器完成表单→303→成功页验证。仍保留严格 Host/Origin 校验，拒绝 `null`、缺失和跨站来源，禁止跨源 referrer，且不降低到接受任意来源。17 项密钥入口与 Jev 旁路测试通过。此浏览器验证不是 Jev 调用，也未保存用户密钥。
